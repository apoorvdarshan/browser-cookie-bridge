Transfer support

Exactly what moves—and what never does.

DataSupportWhat to expect
Cookies & sessions Default

Supported values, domain, path, expiry, security, SameSite, and partition attributes.

History URLs Optional

URLs transfer; original visit times and page titles cannot be preserved.

Full site data Optional

For Codex, compatible Local Storage, IndexedDB, session, and service-worker stores can be replaced from a closed source profile with backup and rollback. Browserless uses its separate fitted cloud capture.

Passwords Never

Chromium extensions cannot read the browser password store.

Bookmarks & autofill Never

Bookmarks, payment data, autofill, and iCloud Keychain remain untouched.

Straight answers

Before you move a session.

Still unsure? Open a GitHub issue without including cookie values, tokens, or private browser data.

Report a bug ↗
Why must Codex be closed?

Codex can overwrite or ignore offline database changes while its Chromium process is running. By default the app blocks direct import until Codex is completely closed. You may optionally enable automatic restart for manual syncs: the app force quits Codex, waits for its database to close, transfers and validates the data, then reopens Codex only after success. Scheduled and login syncs never force quit it.

Do other browsers need to be closed?

No for cookie-only extension transfers. Codex must be closed for direct import. When Full site data is enabled, the selected source browser must also be closed because Local Storage and IndexedDB use live LevelDB files. For manual syncs, the optional Restart both automatically switch can force quit the source and Codex, then reopen only the apps that were running after a successful transfer. Browserless uploads likewise require a closed source profile.

What leaves my Mac with Browserless?

Only after you select Browserless Cloud and click Upload, cookies, local storage, and IndexedDB from the chosen profile are sent directly to your selected Browserless region. The app first measures local sizes without reading their contents, then reports progress and any origins omitted to fit Browserless's 2 MB serialized-profile cap. History and saved passwords are excluded. The token stays in macOS Keychain, CLI telemetry is disabled, and cloud uploads never run on a schedule or at login.

Does this move passwords?

No. Browser extensions cannot access Chromium's password store. Browser Cookie Bridge does not access passwords, Keychain items, payment data, bookmarks, or autofill.

Does it overwrite all destination cookies?

The importer merges selected records using their cookie identity fields. Existing unrelated destination cookies remain in place. Codex is backed up before any replacement.

Will every website stay signed in?

Not always. Full site data improves compatibility by adding origin storage beyond cookies, but some sites bind sessions to a device, browser, hardware-backed credential, IP address, or other risk signals and may still ask you to sign in again.

Do I need Node.js or Xcode?

No when you use Homebrew or the DMG. Node.js and Xcode Command Line Tools are needed only for the npm and source installation methods.

Will macOS trust the downloaded app?

Yes. Public DMGs are SHA-256 verified, signed with the project's Apple Developer ID, and notarized by Apple. Open the DMG, drag the app to Applications, and launch it normally.

What if I previously installed through npm?

The DMG and npm build share the same bundle ID, settings, and updater. The Applications copy becomes canonical; a stale matching copy in your user Applications folder is moved to the Trash instead of running twice.

Is the npm package live?

Yes. Install the latest public release with npx browser-cookie-bridge install-app or inspect it on npm.
